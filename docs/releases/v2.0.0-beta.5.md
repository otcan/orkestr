# V2.0.0-beta.5: Linux beta, Codex-only setup (pre-release)

Self-hosted Orkestr conversations with your own Codex CLI login; Claude is
optional. This is a GitHub pre-release; expect breaking changes. It follows
[v2.0.0-beta.4](v2.0.0-beta.4.md).

## Changed since beta.4

- **Codex alone is enough to configure (#409).** `orkestr-beta configure` now
  requires only the Codex login. In beta.4 it answered `provider_login_required`
  unless both Codex and Claude were signed in. Claude is optional; whether it was
  signed in is recorded once at configure time. Without Claude, Fast replies run
  on Codex. Installs configured on beta.4 keep their Claude setup.
- **The first screen explains how to connect models (#409).** A signed-in owner on
  an install without models now sees "Models are not connected yet" with the
  steps (sign in to Codex inside the container, run configure, restart, reload)
  instead of only "Deep is unavailable".
- **API keys do not work.** Codex must use the ChatGPT device sign-in
  (`orkestr-beta login codex`, which runs `codex login --device-auth`). An OpenAI
  API-key login is refused when the first window opens.

## Docker quick start

Requires Linux x86_64, Docker Engine with Compose v2, git, 8 GiB RAM, 25 GiB free
disk and a ChatGPT account for Codex. A Claude account is optional.

```sh
git clone --branch v2.0.0-beta.5 https://github.com/otcan/orkestr.git && cd orkestr
printf 'ORKESTR_SOURCE_COMMIT=%s\n' "$(git rev-parse HEAD)" > v2/packaging/oss/.env
docker compose -f v2/packaging/oss/compose.yaml up -d --build          # builds from source: about 10-30 minutes
docker compose -f v2/packaging/oss/compose.yaml exec --user 10001:10001 orkestr cat /state/bootstrap.token
```

Open **http://127.0.0.1:19822** and choose **First-time setup**. Paste the token,
then pick a username and a password of at least 12 characters. On a remote
server, run `ssh -L 19822:127.0.0.1:19822 server` first and use the same URL on
your own computer. Then connect a model:

```sh
docker compose -f v2/packaging/oss/compose.yaml exec orkestr orkestr-beta login codex    # shows a link + code; sign in to ChatGPT
docker compose -f v2/packaging/oss/compose.yaml exec orkestr orkestr-beta login claude   # optional
docker compose -f v2/packaging/oss/compose.yaml exec orkestr orkestr-beta configure      # asks for your Orkestr username + password
docker compose -f v2/packaging/oss/compose.yaml restart orkestr
```

Reload the page and send a message. Stop with `docker compose -f
v2/packaging/oss/compose.yaml down` (data stays in the named volumes), start
again with `up -d`, and remove everything including logins and chats with
`down -v`. See the full [V2 README](../../v2/README.md).

## Install time and what is not included

- **No container image is published. The quickstart builds Orkestr from source on
  your machine, which takes roughly 10–30 minutes.**
- **Gmail and LinkedIn job tracking are not part of this beta.** The optional
  job-tracker recipe reads only selected, synchronized local Thunderbird Inbox/Sent
  folders on the computer running Orkestr; the Docker install cannot see host mail.
- **Known limitation:** the job tracker cannot add rows from a chat message.
  Rows come only from the mail recipe above.
- Desktop, macOS, Windows, ARM, mobile, turnkey WhatsApp/mail setup and multi-user
  hosting are deferred. Upgrade, rollback and stopped-state restore are not yet
  qualified operations.

## Security and state

Unchanged from beta.4. One trusted owner per instance. The agent runs as non-root
UID 10001 with all five capability sets empty and full tool access within the
container's Unix permissions. Use only the supplied state/credential named
volumes; never mount a host home, sensitive host paths or the Docker socket.
Publish on localhost or behind authenticated HTTPS ingress. See the
[security model](../../v2/README.md#security-model).
