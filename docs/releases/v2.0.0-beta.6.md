# V2.0.0-beta.6: one docker run, browser setup, arm64 (pre-release)

Self-hosted Orkestr conversations with your own Codex login; Claude is optional.
This is a GitHub pre-release; expect breaking changes. It follows
[v2.0.0-beta.5](v2.0.0-beta.5.md).

## Changed since beta.5

- **Prebuilt image, one command (#413).** A multi-arch image (linux/amd64 and
  linux/arm64) is published at `ghcr.io/otcan/orkestr:v2.0.0-beta.6` by CI, which
  builds and smoke-tests each architecture natively. Build provenance is attested
  for the tested image archives. V2 images use only `v2.0.0-beta.*` tags; `:latest`
  and `v0.*` remain the V1 image. No source build or Compose is needed.
- **Setup entirely in the browser (#414).** The first-time setup token is printed
  in `docker logs orkestr`. After creating your account, **Connect models** starts
  the official Codex device sign-in and shows its link and one-time code on the page.
  Claude is optional: you paste back the code Claude shows you.
  **Activate models** binds your account and switches on the models without a
  container restart. No `docker exec` is needed. The page shows only the official
  link and code, never provider tokens. It needs your signed-in session, and its
  service is switched off once the install is configured.
- **Native arm64, including Apple Silicon (#412).** Docker Desktop on an M-series
  Mac runs the arm64 image natively. Codex and Claude CLIs are pinned per
  architecture by checksum. Source builds also work natively on arm64.
- **Only one extra permission.** The container needs only `--cap-add SYS_PTRACE`
  (the root manager verifies the exact server binary it started). It sets
  no-new-privileges itself, and every agent process runs as UID 10001 with all
  five capability sets empty.
- The CLI path (`orkestr-beta login codex`, `configure`) still works and no
  longer needs a restart after `configure`.

## Quick start

Requires Docker Engine on Linux (x86_64 or arm64) or Docker Desktop on an Apple
Silicon Mac, about 2 GB of memory for the container, and a ChatGPT account for
Codex. A Claude account is optional.

```sh
docker run -d --name orkestr --cap-add SYS_PTRACE -p 127.0.0.1:19822:19823 \
  -v orkestr-state:/state -v orkestr-credentials:/credentials \
  ghcr.io/otcan/orkestr:v2.0.0-beta.6
docker logs orkestr 2>&1 | grep 'First-time setup token'
```

Open **http://127.0.0.1:19822**, choose **First-time setup**, paste the token and
pick a username and a password of at least 12 characters. Then choose **Connect
models**, sign in to Codex with the link and code shown, optionally sign in to
Claude, and choose **Activate models**. On a remote server, run
`ssh -L 19822:127.0.0.1:19822 server` first and use the same URL locally.

Data and logins stay in the named volumes across `docker restart`,
`docker stop`/`docker start` and replacing the container with a newer image. To
remove everything, run `docker rm -f orkestr && docker volume rm orkestr-state
orkestr-credentials`. See the full [V2 README](../../v2/README.md).

## What is not included

- **Gmail and LinkedIn job tracking are not part of this beta.** The optional
  job-tracker recipe reads only selected, synchronized local Thunderbird Inbox/Sent
  folders on the computer running Orkestr; the Docker install cannot see host mail.
- **Known limitation:** the job tracker cannot add rows from a chat message.
  Rows come only from the mail recipe above.
- **API keys do not work.** Codex must use the ChatGPT device sign-in.
- **arm64 note:** the bounded provider sandbox and the workspace command/job
  sandbox are still Linux x86_64 only. The Docker image does not use them (it
  runs providers in the container's full-access profile), so this does not affect
  the Docker install. Docker Desktop on Intel Macs and Windows runs the amd64
  image but is untested.
- Desktop and mobile apps, turnkey WhatsApp/mail setup and multi-user hosting are
  deferred. Upgrade, rollback and stopped-state restore are not yet qualified
  operations.

## Security and state

One trusted owner per instance. The agent runs as non-root UID 10001 with all
five capability sets empty and full tool access within the container's Unix
permissions. Use only the two named volumes; never mount a host home, sensitive
host paths or the Docker socket. Publish on localhost or behind authenticated
HTTPS ingress. See the [security model](../../v2/README.md#security-model).

## Acceptance

Each architecture's image is built natively in CI from the tagged commit and
passes the fresh-install checks with exactly the one-command flags, using
**zero real provider accounts, logins or inference**. The checks include browser
setup up to the Codex device code. Real provider answers are covered by the
automated acceptance run in the [release checklist](../v2/public-beta-checklist.md);
the release is promoted only after it passes.
