# V2.0.0-beta.4: first public Linux beta (pre-release)

Self-hosted Orkestr conversations with your own Codex and Claude CLI logins.
This is a GitHub pre-release; expect breaking changes.

## Included

- Linux x86_64 Docker source build and Compose with the web UI.
- Codex and Claude using the owner's official CLI login inside the container,
  with private logins retained in a separate named volume.
- Conversations with Fast/Deep, timers/digests, agent timers, scoped thread asks,
  result review, Stop and explicit provider handoff with a reviewed context summary.
- Same-build #265 server/UI tarball, paired receipt and checksums, attached to the
  release for advanced web/API use. The tarball does not install provider
  management; Compose is the supported provider setup path.

## Install time and what is not included

- **No container image is published. The quickstart builds Orkestr from source on
  your machine, which takes roughly 10–30 minutes** (8 GiB RAM, 25 GiB free disk).
- **Gmail and LinkedIn job tracking are not part of this beta.** The optional
  job-tracker recipe reads only selected, synchronized local Thunderbird Inbox/Sent
  folders on the computer running Orkestr; the Docker install cannot see host mail.
- Desktop, macOS, Windows, ARM, mobile, turnkey WhatsApp/mail setup and multi-user
  hosting are deferred. Upgrade, rollback and stopped-state restore are not yet
  qualified operations.

## Security and state

One trusted owner per instance. The agent runs as non-root UID 10001 with all
five capability sets empty. Its tools have full access within the container's
Unix permissions and can read its own provider logins. The root manager's
SYS_PTRACE capability is restricted to the container PID namespace for exact
process verification; it is absent from provider descendants. No privileged
mode, SYS_ADMIN, host PID namespace or seccomp override is required.

Use only the supplied state/credential named volumes; never mount a host home,
sensitive host paths or the Docker socket. Publish on localhost. Remote access
requires authenticated ingress with an exactly matching origin; the quickstart
uses SSH forwarding to its fixed localhost origin. See the full
[security model](../../v2/README.md#security-model).

## Acceptance

The tagged commit passed exact-source Rust, browser, Node and image CI. Its clean
public-source image passed 15 fresh-install checks through account creation, real
UI/WASM, empty state/credentials, CLI presence, capability boundaries, generated
package validation and restart persistence, using **zero real provider accounts,
logins or inference**. Real provider answers are covered by the owner's manual
acceptance in the [release checklist](../v2/public-beta-checklist.md).
