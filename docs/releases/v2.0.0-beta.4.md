# V2.0.0-beta.4 candidate — first public Linux beta

This is a **release candidate for review**, not a published tag or image.
The version continues the existing beta.3 line. Manual owner acceptance and
explicit publication approval are required before creating the tag.

## Included

- Linux x86_64 Docker source build and Compose with the web UI.
- Codex and Claude using the owner's official CLI login inside the container,
  with private logins retained in a separate named volume.
- Conversations with Fast/Deep, timers/digests, result review, Stop and explicit
  provider handoff with a reviewed context summary.
- Same-build #265 server/UI tarball and checksums, for advanced web/API use.
  The tarball does not install provider management; Compose is the supported
  provider setup path.

## Security and state

One trusted owner per instance. The agent runs as non-root UID10001 with all
five capability sets empty. Its tools have full access within the container's
Unix permissions and can read its own provider logins. The root manager's
SYS_PTRACE capability is restricted to the container PID namespace for exact
process verification; it is absent from provider descendants. No privileged
mode, SYS_ADMIN, host PID namespace or seccomp override is required.

Use only the supplied state/credential named volumes; never mount a host home,
sensitive host paths or the Docker socket. Publish on localhost. Remote access
requires authenticated ingress with an exactly matching origin; the quickstart
uses SSH forwarding to its fixed localhost origin. See the full
[security model](../../v2/README.md#security-model).

## Acceptance and limitations

Implementation base `9984b7f5bb2585bf4462653f7778467600dbe2ee` passed exact-source
Rust, browser, Node and image CI. Its clean public-source image passed 15 checks
through account creation, real UI/WASM, empty state/credentials, CLI presence,
capability boundaries, generated package validation and restart persistence.
These checks used **zero real provider accounts, logins or inference**.

The final release candidate needs its own exact-source CI and the owner's real
first Codex/Claude answers, follow-up, Fast/Deep, review/Stop, handoff and one
scheduled timer. These gates remain in the [release checklist](../v2/public-beta-checklist.md).

The job tracker is an optional recipe; bounded checks and unresolved thread
evidence do not prove full mailbox catch-up. Desktop, macOS, Windows, ARM,
mobile, turnkey WhatsApp/mail setup and multi-user hosting are deferred.

No image is published by the build workflow. Upgrade, rollback and stopped-state
restore acceptance must be recorded before advertising those operations.
