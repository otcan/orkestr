# Fresh attachment saved-byte qualification preparation

This is a source proposal, not browser acceptance or production manager integration.
The previous failed receipts remain unchanged. No historical download root is reused.

The isolated runner must consume a newly sealed matching server/web pair and retain
its manifest, executable, inventory and harness hashes before activation. Existing
registered browser and canonical desktop lease are required; no new browser process.

Isolation owns the trusted provisioning and kernel-seal helper. Its reviewed launcher
must create a random new owned root with browser traversal through every ancestor,
browser-only capture write access, and retained directory identity. The harness must
not chmod historical roots, select arbitrary helper paths, or run privilege changes.
UID differences must be recorded without tokens or profile reads. Provisioning source
and exact helper hashes require root review before execution.

The context adapter must create one owned context, install context-scoped
allowAndName download behavior and listeners before ready, bind the exact GUID from
willBegin to completed progress, and reject foreign contexts, GUID changes, cancellation,
excess bytes and event floods. No filename-based filesystem search is permitted.
The helper seals the completed GUID file against writers before bounded read/hash
and exact-owned unlink/absence confirmation. The consumer in
`v2/acceptance/browser/attachment-saved-bytes.mjs` validates these receipts and actual
bytes. It does not implement or claim the helper's authority guarantees.

A supervisory finally block must detach/join listeners, close only the issued
context, join helper work, release seals and remove only proven owned roots. Unknown
cleanup is a failed qualification with retained evidence, never a success. Browser
processes and other contexts remain untouched; canonical lease release follows joined
cleanup. The adapter must bound each call; the consumer's polling deadline alone
cannot cancel a hung adapter operation.

Next wiring is intentionally gated on Isolation's concrete reviewed provisioning
and context adapter handoff. Existing attachment-runner is unchanged and must not
be used as a saved-byte successor: its old local filename polling remains historical.
A fresh run must retain exact GUID completion, actual read/hash/deletion receipts,
context cleanup, pair identity and all failed attempts. Thread-file copies only;
no assistant message association or production session/revocation qualification.
