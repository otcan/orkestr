# Independent attachment roundtrip oracle handoff

Migration reserves only these new paths for the independent synthetic oracle:

- `v2/acceptance/attachment_roundtrip_oracle.py`
- `v2/fixtures/migration-audit/attachments/`

Core owns attachment authority, manifest storage and Store contract. UI owns
new presentation/download verification files. Server route registration remains
with the server owner. This handoff defines acceptance requirements, not an ABI,
route, schema or alternative attachment store.

## Contract required before oracle implementation

Core must publish an immutable source revision specifying owner/conversation
scope, manifest/reference identifiers, filename/media-type normalization,
unsigned byte-length bounds, SHA256 encoding, maximum size, authenticated
download route/status/headers and tombstone/missing behavior. Export/import
must specify exact reference remapping and immutable provenance. UI and
Migration consume that same published contract. No guessed routes or DTOs are
safe to use as a compatibility promise.

The oracle adapter will call the actual published implementation against fresh
synthetic storage. It must not implement its own pretend importer/download
service and then claim application acceptance. The published pure seam is Core `9788ef14d0d86ecdaa5dde14522761194064cfb4`,
`attachment_integrity::{validate_attachment_bytes, validate_attachment_copy}`.
The Python preparation command verifies exact committed source, independently
checks four byte vectors and emits two Rust integration-test files for an
admitted disposable build. Install both files together into the Store tests
directory and select `--test attachment_integrity_oracle`. It never invokes
Cargo or edits the checkout itself. Rust execution is explicitly unexecuted
until an admitted build runs it. Persisted application roundtrip tests remain
unimplemented pending the actual ports.

## Independent expected results

Use fixed fake identities and generated byte sequences including empty bytes,
NUL/non-UTF8 bytes, newline variants and an attachment referenced more than once.
Retain the original byte strings outside the producer, independently compute
SHA256/length, and compare downloaded bytes after export/fresh dormant import.
A roundtrip must preserve reference multiplicity, order and scoped provenance
according to the agreed contract, without resurrecting native admissions,
credentials, routes, timers or other execution authority.

Negative cases must cover changed bytes, truncation, advertised/actual oversize,
wrong digest/length, missing blob, tombstone, duplicate/conflicting identity,
foreign owner/conversation/reference, partial export/import and replay conflict.
An identical replay must not duplicate blobs or references. A failed import must
not leave a usable partial target. Failure categories and status codes must come
from the agreed contract, rather than invented oracle semantics.

UI additionally verifies bounded streamed length and digest before exposing a
save action, plus owner/logout late-response fences. That client work does not
replace independent server authorization or byte-integrity checks. The oracle
uses no production data, external calls, preview/execution, or live import.
