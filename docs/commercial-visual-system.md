# Commercial Visual System

The commercial surface should feel operational, controlled, technical, and
high-value—not like an AI template or generic agency portfolio.

## Tokens and components

- Warm paper `#f2efe6`, near-black ink `#171915`, dark proof `#101a14`
- Rust accent `#b63718`, muted text `#5f635a`
- Large direct headings and restrained monospace operating labels
- One-pixel boundaries, minimal radius, high-contrast 44px controls
- Requirement-to-operation diagram with switchable illustrative requirements
- Five BUILD · REPLACE · FIND · COLLECT · AUTOMATE cards
- “Bring us an ugly problem” statements and illustrative project briefs
- Delivery phases, browser integration map, approval evidence, Orkestr Console,
  deployment columns, FAQ, Project Discovery form, and Workflow Audit form

Examples must be labelled as illustrative. The Console remains product proof,
not a fake customer dashboard. Avoid robots, avatars, glowing brains, generic
gradients, stock photography, fake logos, testimonials, and unsupported metrics.

## Responsive and accessible behavior

Semantic source order is content order. Desktop grids collapse below 760px;
the requirement diagram, solution cards, project briefs, Console, delivery
phases, and forms stack without page-level overflow. Navigation remains keyboard
reachable through native `details`. Project Discovery stays in the mobile menu.

Focus is visible, diagrams have text labels, controls do not depend on color or
motion, and `prefers-reduced-motion` suppresses smooth movement and transitions.
